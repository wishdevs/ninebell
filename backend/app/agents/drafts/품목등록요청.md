# 품목등록요청 처리 — 행위 표기 (초안·미구현)

- 에이전트 **없음** — 업무 절차를 표기로만 옮긴 단계
- 표기법 [../ACTIONS.md](../ACTIONS.md)

품의로 접수된 품목등록요청을 받아 견적을 요청하고, 도착한 견적서로 엑셀을 만들어
품목과 단가를 일괄등록한 뒤 품의를 종결하는 업무다.

> **이 문서는 사용자가 구술한 절차를 표기로 옮긴 것이다.** 화면 조작을 라이브로 확인하지
> 않았으므로 `미검증` 이 붙은 줄은 전부 가설이다. 구현 전에 헤드리스 프로브로 확인해야 한다.

---

## 1단계 · 품의 확인과 견적요청

```
변경  [로그인]
변경  [유형전환]                                                       미검증
변경  [메뉴이동]    미결함(품의)                                       미검증
읽기  [읽기]        품의: 나인벨-2026-13922
                    기안자 박나형 · 시행자 윤병민
읽기  [읽기]        첨부: 품목등록요청서 · 도면
변경  [경로열기]    \\192.168.0.64\생산공유\업무출도\도면관리
                    \품목코드등록요청\도면\윤병민 (IMP본부, 진공팀)     미검증
변경  [폴더생성]    2026-13922-박나형          (없을 때만)
변경  [파일첨부]    품목등록요청서 · 도면
발신  [메일발송]    제목에 '2026-13922' 포함   승인필요                미검증
대기  [메일대기]    견적서 도착 — 세션 종료 · 상태 보존(키 2026-13922)
```

## 2단계 · 견적 반영과 표 가공

```
변경  [파일복사]    구매거래처단가일괄등록 샘플양식.xlsx  →  2026-13922-박나형
변경  [파일복사]    품목일괄등록 개정.xlsx               →  2026-13922-박나형
읽기  [표읽기]      견적서 → 품목별 단가
변경  [표쓰기]      LIST.매입단가  ←  견적 단가          확인 행수 일치   중단
읽기  [분류]        'P' 포함하면 판금품                                 미검증
변경  [메뉴이동]    구매거래처정보                                      미검증
읽기  [조회]        판금
읽기  [읽기]        거래처코드 → 20039                                  미검증
변경  [표쓰기]      LIST.주거래처  ←  20039
변경  [열대응]      LIST  →  품목일괄등록 개정.xlsx
                      품목코드    →  품목코드
                      품목명      →  품목명
                      규격        →  순중량   (단위 제거)              미검증
                      소재(재질)  →  재질
                      주거래처    →  주거래처코드
                      그 외       →  같은 이름 열 그대로
변경  [행삭제]      표.샘플 행
```

`LIST` 는 `2026-13922 품목요청등록 LIST-박나형.xlsx` 를 가리킨다.

```

변경  [값설정]      통합품목 · 회사품목 · 공장품목  모두 체크

                      단가      →  단가
변경  [메뉴이동]    구매거래처단가일괄등록                              미검증
변경  [파일올리기]  구매거래처단가일괄등록 샘플양식.xlsx
확정  [저장]        승인필요        확인 등록건수 일치                  중단
```

## 4단계 · 품의 종결

```
변경  [메뉴이동]    미결함 → 나인벨-2026-13922
변경  [값설정]      처리결과: 등록완료
금지  [승인]        초기엔 사람이 직접 — 라이브 10회 검증 후 승격
```

## 기존 에이전트와 다른 점

**단일 세션으로 완주할 수 없다.** 견적서 도착까지 며칠이 걸린다. 지금까지 만든 8개는 전부
'실행 → 완주 → 종료' 였는데 이것은 **중단·재개형**이다. 품의번호를 상태키로 잡고
1단계 완료 시점을 저장해야 한다.

**브라우저 밖으로 나간다.** 화면 자동화 라이브러리 옆에 **파일서버 어댑터**(공유 폴더)와
**메일 어댑터**가 새로 필요하다. 작은 작업이 아니다.

**되돌릴 수 없는 지점이 넷이다.** 메일 발송 · 품목 저장 · 단가 저장 · 승인.
기존 에이전트는 저장 하나뿐이었다. 특히 **메일은 회수가 불가능**하므로 저장보다 게이트를
더 엄격히 둬야 한다.

**핵심이 화면 조작이 아니라 데이터 변환이다.** `[열대응]` 두 번이 이 업무의 실체다.
표 매핑만 떼어 먼저 테스트할 수 있다.

---

## 구현 전에 답이 필요한 것

정확도를 직접 좌우하는 넷 — 사람에게 물어야 한다.

1. **공유 폴더 경로 구분** — 원문에서 구분자가 뭉개져 폴더 경계가 불확실하다
   (`생산 공유` / `업무출도` / `도면 관리` 로 나뉘는 것이 맞는지)
2. **판금 판정 위치** — 'P 포함' 이 품목코드인지 품목명인지
3. **거래처코드 20039** — 판금 고정값인지, 조회 결과에 따라 달라지는지
4. **순중량 파싱 규칙** — `10kg` → `10` 인가. 소수·범위 표기는 어떻게 되는가

헤드리스 프로브로 직접 확인할 수 있는 것들.

5. 견적요청 메일 수신처를 어디서 얻는가
6. 견적서 도착을 어떻게 감지하는가 — 메일함인지 폴더인지
7. 품의 확인에 필요한 사용자유형과 미결함 메뉴 ID
8. 품목일괄등록 · 구매거래처단가일괄등록 · 구매거래처정보 메뉴 ID
9. 업로드 실패를 화면이 어떻게 알리는가 — 모달인지 토스트인지
