# 구매발주 — 프로세스 정의 (purchase-order)

> SCM-구매 계열 첫 에이전트. 결의서(GLDDOC00300) 패밀리가 아니라 **구매 3화면 파이프라인**이다:
> ① 프로젝트BOM구매요청[나인벨](PUOPRQ00200) → ② 구매요청처리[나인벨] → ③ 구매발주일괄입력[나인벨].
> 상태: **v0.1 — 사용자 구술(2026-08-12) 초안 + 읽기 전용 라이브 프로브 완료(2026-08-13, 부작용 0).
> 진입·검색·그리드 읽기 경로 확정. 쓰기 경로(선택 세터·저장)·셀프 결재는 미실측.**
> 화면 흐름 확정본(프론트): 구매발주 데모(`purchase-order-demo`) 계획서 —
> `src/components/live/simulation/purchase-order/` (`buildPlanPayload` 가 실행 파라미터 계약 초안).

## 개요

사용자가 **계획서(실행 전 플래너)** 에서 실 프로젝트를 검색해 BOM 을 불러오고, 3레벨 모듈을
발주단위로 묶어 발주단위별 구매사유·납기예정일과 거래처 그룹별 실거래처·납기·비고를 확정한다.
에이전트는 그 계획서를 받아 ERP 반복 루프(발주단위마다 조회→선택→입력→저장)를 대신 돈다.
반복 입력을 그때그때 받지 않고 최초 1회 계획서로 일괄 수령하는 것이 설계의 핵심.

## 확정된 업무 결정(사용자, 2026-08-12~13)

- **D1 입력 방식**: **실행 중 HITL**(2026-08-13 사용자 확정). 실행 시작 → 로그인/SCM-구매/화면
  진입 → 프로젝트 선택 개입 → BOM 조회 → **계획서 개입**(전체폭 — 데모 `purchase-order-demo`
  화면 흐름 재사용: 발주단위 묶음 + 구매사유·납기 + 거래처 지정) → 발주단위 반복 실행.
  실행 전 REST 조회 방식은 기각(세션 관리 신설·조회 대기 UX 부담). eap-cancel 목록 HITL 선례.
- **D2 사용자유형**: 로그인 후 **SCM-구매** 선택(2026-08-13 사용자 지정). 검증: ✅ 2026-08-13
  프로브 — `.user-info` 패널 라벨 정확히 'SCM-구매'(옵션: 회계사용자(예외)/인사사용자(예외)/SCM-구매),
  이트라이브2 계정 보유, 기존 `ensure_user_type(page, "SCM")` 이 **무수정** 통과
  (`menu_schemas.USER_TYPE_SCM` 별칭 기등록).
- **D3 화면 ① 고정값**: 구매그룹=**나인벨**, 구매조직=**나인벨** — 검증: ✅ 진입 시 자동
  기본값(코드 1000), 통화 KRW. 상단 구매사유 입력은 **비운다**(구매사유는 반복 루프에서
  발주단위별 입력). 딥링크 3종 확정(✅ `navigate_menu()` 무수정 진입):
  ① `/PU/PUOPRQ00200_X20616` ② `/PU/PUOPRQ00300_X20616` ③ `/PU/PUOORD02000_X20616`
  (모듈코드 PU + 나인벨 커스텀 접미 `_X20616`).
- **D4 이동요청 선행(화면 ①, 1회)**: ⚠ **정정(프로브 실측)** — 진입 시 구매요청·이동요청
  체크박스가 **둘 다 체크 상태**다. "이동요청만 체크"는 **구매요청을 해제(uncheck)** 하는
  스텝이다. 이후: 조회 → 리스트 **모두 선택** → 이동출고저장위치=**공용자재**,
  이동입고저장위치=**프로젝트** → 저장. ⚠ 비가역(저장 게이트 뒤). 체크박스↔`MV_FG`/`PUR_FG`
  필터 연동·저장위치 적용 UI — 검증: ❓ (토글 프로브 미실행).
- **D5 반복 루프 = 발주단위(화면 ①)**: 이동요청 해제·구매요청만 체크 → **다시 조회(초기화: 예)**
  → 계획서의 발주단위 순서대로: 3레벨 모듈 선택(1개 이상) → 납기예정일 + 구매사유 입력 →
  저장(= 구매요청 저장 1회 = 발주번호 1건). ⚠ 비가역. 3레벨 선택 **세터** — 검증: ❓
  (트리그리드 체크 getter 는 확정 — `getCheckedItems()`/`checkChildren()`; 세터는 프로토타입
  스캔에 없어 쓰기 프로브에서 실클릭 좌표로 확정 예정. setValue 류 우회 금지 원칙).
- **D6 구매사유 기본값**: 외주조립 모듈이면 `[프로젝트명] [부품명]`(예:
  `CX85-137 · 12CH PROCESS BUFFER`, 복수면 `·` 연결), 그 외 빈 값 — 사용자 수정 가능(계획서에서 확정).
- **D7 셀프 결재(화면 ②)**: 공장=**나인벨**, ①에서 등록한 항목 선택 → 셀프 결재. ⚠ 비가역 —
  **결재 실클릭은 상신 금지 원칙의 예외 승인 필요. 사용자 명시 승인 전 이 스텝은 게이트 닫힘**
  (voucher 3종 선례: 2026-08-07 승인 + 가역 경로 확보 후 개방). 회수(취소) 수단 존재 여부 — 검증: ❓.
- **D8 화면 ③ 거래처 적용**: 구매발주유형=**원재료** → 구매요청 버튼 → WBS 요소로 조회 →
  품목거래처명 '가공품' 행 일괄 선택 → 변경 거래처(기본 **해룡**) 적용 → '판금품' 행 → (기본
  **알파테크**) 적용 → 리스트 모두 선택 → 적용. ⚠ '적용' 이후 비가역 단계 존재 — 검증: ❓.
- **D9 거래처 그룹별 마감(화면 ③)**: 거래처별 그룹 행을 하나씩 열어 하위 전체 선택 →
  납기예정일 입력, 비고 수정 가능. 납기 파생 규칙(계획서와 동일): 가공품=발주 납기,
  그 외=발주 납기 −7일에서 구간 내 평일 공휴일·대체공휴일 수만큼 반복 앞당김 + 최종일이
  주말/공휴일이면 직전 영업일(프론트 `dates.ts` 와 동일 알고리즘 — 백엔드 이관 시 단일소스화).
  비고 기본 = `가공품 거래처(<가공품 거래처명>) 직배송`.
- **D10 프로젝트 검색**: 검증: ✅(부분) 2026-08-13 프로브 — **"프로젝트 도움창" 코드피커**
  (자동완성 아님). 오픈은 라벨 '프로젝트' 우측 돋보기(기존 `js_lib.PROJECT_PICKER_BOX_JS`
  무수정 동작), 검색어 입력 `#keyword`, 결과는 플랫 `.dews-ui-grid`. 필드 매핑은 WBS 스키마가
  아니라 **`PJT_NO`(코드)/`PJT_NM`(명)** + `START_DT`/`END_DT`/`RSPNBER_EMP_NM`(담당)/
  `PJT_ST_NM`(상태). 'CX85-137' 검색 = 정확히 1건(코드 2297) 확인. 백엔드 검색 계약 초안:
  `{"keyword":"CX85-137"}` → `[{"code":"2297","name":"CX85-137, 12CH PROCESS","start_date":…,
  "end_date":…,"manager":…,"status":"승인"}]`. 선택 '적용' 클릭은 읽기 규율로 미검증(❓).
  ⚠ 'ZJ90' 검색 시 팝업이 통째로 닫히는 현상 미해소 — **'ZJ90-130, 8CH BS PROCESS' 는 실재
  프로젝트**(2026-08-13 사용자 확인)이므로 검색 트리거/타이밍 문제로 보고 재프로브 대상.
- **D11 프리필 불신(프로브 실측)**: 프로젝트 필드는 세션/계정에 이전 값이 남아 자동 프리필된다
  (진입 즉시 'CX85-137, 12CH PROCESS' 코드 2297 채워짐). 자동화는 프리필을 신뢰하지 말고
  **항상 명시적으로 재검색·선택**한다.

## ⚠ 저장·결재 주의

- 저장(D4·D5)·거래처 적용(D8)·납기 확정(D9)은 전부 게이트 뒤. 스크립트 안정화 중 게이트 닫음.
- **셀프 결재(D7)는 사용자 명시 승인 전 미구현/게이트 닫힘.** 승인 시에도 회수 경로(결재취소류)
  실측·확보가 선행 조건(eap-approval-cancel 선례).
- e2e 반복 테스트 전 **구매요청 삭제 수단**(F6 상당) 존재를 먼저 실측한다. 삭제 수단이 없으면
  비가역 동사 직전에서 멈추는 사이클로 설계한다(리포 안전 경계).

## BOM 트리그리드 실측(2026-08-13 프로브 — ✅)

- 구현체는 **`.dews-ui-treegrid`**(RealGrid **TreeGrid**) — 기존 nbkit 이 다루던 `.dews-ui-grid`
  (플랫)와 다른 신규 위젯 타입. 접근: `$('.dews-ui-treegrid').data('dewsControl')._grid`.
- 데이터 컬럼 42개 — 엑셀 내보내기 헤더와 일치(fieldName 상세는 프로브 아티팩트
  `backend/e2e/artifacts/purchase_order_bom_grid_results.json`).
- **레벨 판정**: `ds.getLevel(itemIndex)` (0-idx: 0=프로젝트/1=장비/2=모듈/3=부품 — 화면 표시
  LV_SQ 는 +1). **부모 연결**: `ds.getParent(itemIndex)` 또는 필드 `UP_PJTBOM_UID_NO`.
- **전량 읽기**: `ds.getJsonRows(0, N-1)` 는 트리그리드에서 **null 반환**(플랫 전용 API — 실측).
  `for i in range(rowCount): getLevel(i) + g.getValue(i, field)` 루프가 유일한 경로(410행 실측 성공).
- **체크 API**: `getCheckedItems()` / `getCheckedRows()` / `checkChildren()`(부모 체크 → 자식
  전파, D9 '하위 전체 선택'과 부합). 단일 행 체크 **세터는 미확정** — 쓰기 프로브에서 실클릭으로.
