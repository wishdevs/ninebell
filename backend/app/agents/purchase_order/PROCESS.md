# 구매발주 — 프로세스 정의 (purchase-order)

> SCM-구매 계열 첫 에이전트. 결의서(GLDDOC00300) 패밀리가 아니라 **구매 3화면 파이프라인**이다:
> ① 프로젝트BOM구매요청[나인벨](PUOPRQ00200) → ② 구매요청처리[나인벨] → ③ 구매발주일괄입력[나인벨].
> 상태: **v0 — 사용자 구술(2026-08-12)·화면 스크린샷·그리드 엑셀 내보내기 기반 초안. 헤드리스 라이브 프로브 미실행.**
> 화면 흐름 확정본(프론트): 구매발주 데모(`purchase-order-demo`) 계획서 —
> `src/components/live/simulation/purchase-order/` (`buildPlanPayload` 가 실행 파라미터 계약 초안).

## 개요

사용자가 **계획서(실행 전 플래너)** 에서 실 프로젝트를 검색해 BOM 을 불러오고, 3레벨 모듈을
발주단위로 묶어 발주단위별 구매사유·납기예정일과 거래처 그룹별 실거래처·납기·비고를 확정한다.
에이전트는 그 계획서를 받아 ERP 반복 루프(발주단위마다 조회→선택→입력→저장)를 대신 돈다.
반복 입력을 그때그때 받지 않고 최초 1회 계획서로 일괄 수령하는 것이 설계의 핵심.

## 확정된 업무 결정(사용자, 2026-08-12~13)

- **D1 입력 방식**: 실행 전 계획서(플래너). 프로젝트 검색(실 ERP 리스트) → BOM 조회 → 발주단위
  묶음 + 구매사유·납기 + 거래처 지정 → 확정 payload 로 실행. HITL 개입 없음(계획서가 개입을 대체).
- **D2 사용자유형**: 로그인 후 회계/인사 선택부에서 **SCM-구매** 선택(2026-08-13 사용자 지정).
  패널 내 정확 라벨·전환 방식 — 검증: ❓ (기존 `#ch_group` 회계/인사 전환 프리미티브 확장 필요 여부 포함).
- **D3 화면 ① 고정값**: 구매그룹=**나인벨**, 구매조직=**나인벨**. 상단 구매사유 입력은 **비운다**
  (구매사유는 반복 루프에서 발주단위별 입력). 필드 셀렉터 — 검증: ❓.
- **D4 이동요청 선행(화면 ①, 1회)**: 이동요청만 체크 → 조회 → 리스트 **모두 선택** →
  이동출고저장위치=**공용자재**, 이동입고저장위치=**프로젝트** → 저장. ⚠ 비가역(저장 게이트 뒤).
  체크박스·저장위치 적용 UI·저장 버튼 — 검증: ❓.
- **D5 반복 루프 = 발주단위(화면 ①)**: 구매요청만 체크 → **다시 조회(초기화: 예)** → 계획서의
  발주단위 순서대로: 3레벨 모듈 선택(1개 이상) → 납기예정일 + 구매사유 입력 → 저장(= 구매요청
  저장 1회 = 발주번호 1건). ⚠ 비가역. 3레벨 선택 방법(트리 체크박스) — 검증: ❓.
- **D6 구매사유 기본값**: 외주조립 모듈이면 `[프로젝트명] [부품명]`(예:
  `CX85-137 · 12CH PROCESS BUFFER`, 복수면 `·` 연결), 그 외 빈 값 — 사용자 수정 가능(계획서에서 확정).
- **D7 셀프 결재(화면 ②)**: 공장=**나인벨**, ①에서 등록한 항목 선택 → 셀프 결재. ⚠ 비가역 —
  **결재 실클릭은 상신 금지 원칙의 예외 승인 필요. 사용자 명시 승인 전 이 스텝은 게이트 닫힘**
  (voucher 3종 선례: 2026-08-07 승인 + 가역 경로 확보 후 개방). 회수(취소) 수단 존재 여부 — 검증: ❓.
- **D8 화면 ③ 거래처 적용**: 구매발주유형=**원재료** → 구매요청 버튼 → WBS 요소로 조회 →
  품목거래처명 '가공품' 행 일괄 선택 → 변경 거래처(기본 **해룡**) 적용 → '판금품' 행 → (기본
  **알파테크**) 적용 → 리스트 모두 선택 → 적용. ⚠ '적용' 이후 비가역 단계 존재 — 검증: ❓.
- **D9 거래처 그룹별 마감(화면 ③)**: 거래처별 그룹 행을 하나씩 열어 하위 전체 선택 →
  납기예정일 입력, 비고 수정 가능. 납기 파생 규칙(계획서와 동일): 가공품=발주 납기,
  그 외=발주 납기 −7일에서 구간 내 평일 공휴일·대체공휴일 수만큼 반복 앞당김 + 최종일이
  주말/공휴일이면 직전 영업일(프론트 `dates.ts` 와 동일 알고리즘 — 백엔드 이관 시 단일소스화).
  비고 기본 = `가공품 거래처(<가공품 거래처명>) 직배송`.
- **D10 프로젝트 검색**: 계획서의 프로젝트 선택은 실 ERP 리스트 검색(예: `ZJ90-130 8CH BSPROCESS`,
  `CX85-137, 12CH PROCESS`). 검색 UI(코드피커 vs 자동완성)·백엔드 검색 계약 — 검증: ❓.

## ⚠ 저장·결재 주의

- 저장(D4·D5)·거래처 적용(D8)·납기 확정(D9)은 전부 게이트 뒤. 스크립트 안정화 중 게이트 닫음.
- **셀프 결재(D7)는 사용자 명시 승인 전 미구현/게이트 닫힘.** 승인 시에도 회수 경로(결재취소류)
  실측·확보가 선행 조건(eap-approval-cancel 선례).
- e2e 반복 테스트 전 **구매요청 삭제 수단**(F6 상당) 존재를 먼저 실측한다. 삭제 수단이 없으면
  비가역 동사 직전에서 멈추는 사이클로 설계한다(리포 안전 경계).
