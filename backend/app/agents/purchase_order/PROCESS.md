# 구매발주 — 프로세스 정의 (purchase-order)

> SCM-구매 계열 첫 에이전트. 결의서(GLDDOC00300) 패밀리가 아니라 **구매 3화면 파이프라인**이다:
> ① 프로젝트BOM구매요청[나인벨](PUOPRQ00200) → ② 구매요청처리[나인벨] → ③ 구매발주일괄입력[나인벨].
> 상태: **v0.1 — 사용자 구술(2026-08-12) 초안 + 읽기 전용 라이브 프로브 완료(2026-08-13, 부작용 0).
> 진입·검색·그리드 읽기 경로 확정. 쓰기 경로(선택 세터·저장)·셀프 결재는 미실측.**
> 화면 흐름 확정본(프론트): 구매발주 데모(`purchase-order-demo`) 계획서 —
> `src/components/live/simulation/purchase-order/` (`buildPlanPayload` 가 실행 파라미터 계약 초안).

## 개요

사용자가 **계획서(실행 전 플래너)** 에서 실 프로젝트를 검색해 BOM 을 불러오고, 3레벨 모듈을
발주단위로 묶어 발주단위별 구매사유·납기예정일과 거래처 그룹별 실거래처·납기·비고를 확정한다.
에이전트는 그 계획서를 받아 ERP 반복 루프(발주단위마다 조회→선택→입력→저장)를 대신 돈다.
반복 입력을 그때그때 받지 않고 최초 1회 계획서로 일괄 수령하는 것이 설계의 핵심.

## 확정된 업무 결정(사용자, 2026-08-12~13)

  화면 흐름 재사용: 발주단위 묶음 + 구매사유·납기 + 거래처 지정) → 발주단위 반복 실행.
  실행 전 REST 조회 방식은 기각(세션 관리 신설·조회 대기 UX 부담). eap-cancel 목록 HITL 선례.

  (`menu_schemas.USER_TYPE_SCM` 별칭 기등록).
- **D3 화면 ① 고정값**: 구매그룹=**나인벨**, 구매조직=**나인벨** — 검증: ✅ 진입 시 자동

  저장. ⚠ 비가역(저장 게이트 뒤). 저장위치 적용 UI — 검증: ❓.
- **D5 반복 루프 = 발주단위(화면 ①)**: 이동요청 해제(구매요청만) → 조회(**확인 다이얼로그

  1회 = 발주번호 1건). ⚠ 비가역. 선택 **세터** — 검증: ❓ (체크 getter 는 확정 —
  `getCheckedItems()`/`checkChildren()`; 세터는 쓰기 프로브에서 실클릭 좌표로. setValue 우회 금지).
- **D5-보충 BOM 레벨 재정정(levelmap 프로브 2026-08-13)**: 트리그리드는 **5레벨**
  (`ds.getLevel()` 0-idx: **0=루트/1=프로젝트(라벨 행)/2=장비/3=SET/4=부품**). 사용자 용어
  '3레벨'(발주단위 선택 대상)은 **getLevel()==3 인 SET 행 15개**('외주조립-*' 등)에 대응.
  구매요청만 필터 = **프로젝트 1 + 장비 1 + SET 15 + 리프 337 = 354행**(xlsx 와 일치.
  루트는 count 밖 — ds 인덱스 0 의 숨은 루트, 데이터 행은 1..count. 한때 '리프 336' 으로
  기록했던 것은 0..count-1 루프가 마지막 행을 놓친 경계 아티팩트 — boundary 프로브로 정정).

  경계 아티팩트 ±1 가능(재실측 시 393/56 예상, 게이트에 미사용). ⚠ 필드 읽기는 반드시
  `ds.getValue` — `grid.getValue` 는 한 행 앞섬(아래 'BOM 트리그리드 실측' 인덱스 공간 함정).
- **D5-보충2 모듈은 하위 부품이 있는 SET 만이다(사용자 확정 2026-08-14)**: 구매요청만 필터를
  적용하면 **4레벨 부품이 한 행도 없는** 프로젝트가 있다 — ZJ90-130 은 17행 = 프로젝트 1 +
  장비 1 + **SET 15**(외주조립-*)뿐이고 리프가 0이다. 이는 **그 SET 들의 발주가 이미 끝났다**는
  뜻이며(리프가 남아 있어야 발주 대상), 계획서에 띄우면 안 된다. 규칙: **parts 가 빈 module 은
  버리고**, 그 결과 module 이 0인 machine 도 버린다(`planner.assemble_planner_bom`). 남은
  모듈이 0이면 `read_bom` 이 `no_modules` 로 **조기 종료**한다(END — 빈 계획서 HITL 금지).
  ⚠ 2026-08-13 에 같은 화면을 보고 넣었던 '자식 없는 SET = 그 행 자체가 구매 대상' 보정은

## ⚠ 저장·결재 주의

- 저장(D4·D5)·거래처 적용(D8)·납기 확정(D9)은 전부 게이트 뒤. 스크립트 안정화 중 게이트 닫음.

  실측·확보가 선행 조건(eap-approval-cancel 선례).

  비가역 동사 직전에서 멈추는 사이클로 설계한다(리포 안전 경계).

## BOM 트리그리드 실측(2026-08-13 프로브 — ✅)

- 구현체는 **`.dews-ui-treegrid`**(RealGrid **TreeGrid**) — 기존 nbkit 이 다루던 `.dews-ui-grid`
  (플랫)와 다른 신규 위젯 타입. 접근: `$('.dews-ui-treegrid').data('dewsControl')._grid`.
- 데이터 컬럼 42개 — 엑셀 내보내기 헤더와 일치(fieldName 상세는 프로브 아티팩트
  `backend/e2e/artifacts/purchase_order_bom_grid_results.json`).
- **레벨 판정**: `ds.getLevel(itemIndex)` — 0-idx **0=루트/1=프로젝트(라벨 행)/2=장비/3=SET/
  4=부품** (levelmap 프로브 재실측 2026-08-13, `/tmp/po-live-refix/levelmap-probe.json`).
  **부모 연결**: `ds.getParent(itemIndex)` 또는 필드 `UP_PJTBOM_UID_NO`.
- ⚠ **인덱스 공간 함정(2026-08-13 blocker 실측)**: 트리그리드에서 `grid.getValue(i, f)` 는
  `ds.getLevel(i)` 보다 **한 행 앞선 데이터**를 돌려준다 — 이 조합으로 읽으면 모듈이 '첫
  부품'으로, 마지막 부품이 '다음 SET 헤더'로 밀린다(스모크 산출물 대조로 발견). 필드는
  반드시 **`ds.getValue(i, f)`**(= `ds.getJsonRow(i)`) 로 읽어야 레벨과 같은 행이다.
  이전 '0=프로젝트/1=장비/2=구조행(접힘)' 매핑은 이 시프트가 만든 오독이었다.
- **전량 읽기**: `ds.getJsonRows(0, N-1)`(범위형)는 트리그리드에서 **null 반환**(플랫 전용 API —
  실측). `for i in 1..rowCount: ds.getLevel(i) + ds.getValue(i, field)` 루프가 유일한 경로
  (**1..count 포함** — 0 은 숨은 루트, 마지막 데이터 행은 i==count. boundary 프로브 실측).
- **체크 API**: `getCheckedItems()` / `getCheckedRows()` / `checkChildren()`(부모 체크 → 자식
  전파, D9 '하위 전체 선택'과 부합). 단일 행 체크 **세터는 미확정** — 쓰기 프로브에서 실클릭으로.
