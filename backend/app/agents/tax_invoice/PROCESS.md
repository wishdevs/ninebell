# 세금계산서 결의서입력 — 프로세스 정의 (tax-invoice)

> 결의서입력(GLDDOC00300) 문서 종류 중 **세금계산서**. 패밀리 인덱스: [../RESOLUTIONS.md](../RESOLUTIONS.md).

> 형제(기본틀 동일): [../hakjagum_grant/PROCESS.md](../hakjagum_grant/PROCESS.md), [../card_collect/PROCESS.md](../card_collect/PROCESS.md).

## 개요
발행 전/후·과세성격·분할 여부에 따라 증빙유형 코드(10종)가 갈리는 결의서. 질문 답과 입력항목은
실행 전 폼으로 받고, **발행 후 케이스는 라이브 중 '전자세금계산서/전자계산서' 팝업의 행을
HITL 로 선택**한다(검증: ❓ D1 — 카드 관례 준용 제안). 분할이면 detail 그리드에 다행 분개.
완주 = 폼값 채움 → F7 실저장(카드 관례, 2026-08-19 사용자 승인). 상신은 사용자가 ERP 에서 직접.

## 확정된 업무 결정(사용자, 시뮬레이션 코드 주석 확정일 병기)
- **D1 입력 방식 (2026-08-20 사용자 재확정 — 종전 설계 뒤집음)**:
  - **발행 전(22/23/24)**: 실행 전 폼에서 전량 입력(단건·사전 확정 가능) → 무개입 완주. ✅ 검증 완료 경로 유지.

    적요는 폼에서 받지 않는다 — **리스트 선택 항목이 복수일 수 있기 때문**. 라이브 개입에서
    **법인카드(card_collect)식 그리드**로: 계산서 행 목록(계산서일·거래처·공급가액·세액·합계·
    승인번호) + 행 선택(복수) + **선택 행별 예산단위·프로젝트·적요 입력** + 일괄 지정.

  - ⚠ 종전 multiselect(선택만) 개입과 폼 사전입력은 이 확정으로 폐기. 검증: ✅ 사용자 확정

## 필수값 검증 체인 (실측 2026-08-19 — F7 이전, draft 단계에서 발생)
"비용분할" 클릭(그리고 추정컨대 F7 도) 순차 필수값 검증에 막힌다 — 토스트 문구가 순서대로:
1. 공급가액 미입력 → **"공급가액(거래금액)이 입력되지 않았습니다."**
2. 예산단위 미입력 → **"예산단위가 입력되지 않았습니다."**
3. 예산 초과(경고성, 저장 차단 아님 — 실측: 초과 상태로도 저장 성공) → **"예산금액을 초과했습니다.[계정코드:계정명]"**
4. **자금과목(FUND_CD)은 계정의 관리항목 구성에 따라 필수** (2026-08-19 headed 세션 정정 —
   Case A 는 이미 채운 상태라 "비필수"로 오판했었다. (제)운반비_일반 은 필수: "계정의 관리항목
   [자금과목] 항목이 입력되지 않았습니다" 반려). **에이전트는 항상 자금과목을 채우는 것을 기본**으로.
   결제방법·자금예정일·결제조건은 저장 비필수. 결제방법(STLM_WAY_CD)은 거래처/예산단위 선택 시
   **자동 기본값 "6"(외상)**.
5. ⚠ **ERP 검증 반려는 한 번에 한 문구만 나온다** — generic("상세그리드에 필수 값…") 뒤에 구체
   문구가 숨어 있을 수 있다. 자동화의 저장 반려 처리는 "문구 확인→해당 필드 해결→재시도" 루프로.
