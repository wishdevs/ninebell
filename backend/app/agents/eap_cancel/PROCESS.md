# 전자결재 상신 취소 — 프로세스 정의 (eap-approval-cancel)

> 전자결재(EAP)에 상신된 문서를 되돌린다. 행위 표기: [FLOW.md](FLOW.md).
> 상태: **v1.0 — e2e 프로브 이식 완료(2026-08-12). 프로브 `e2e/eap_approval_cancel_probe.py`
> 는 실 ERP 에서 2회 PASS(2026-08-07). 그래프 자체의 라이브 실행은 미실시 — 첫 실행은
> 디버그 모드에서 테스트 문서 1건으로 할 것.**
> 관련: [../ACTIONS.md](../ACTIONS.md) 취소 3형제 · [../voucher_receivable/PROCESS.md](../voucher_receivable/PROCESS.md)(상신하는 쪽).

## 개요

회계전표 3종(외상매출·외상매입·미지급금 법인카드)이 **실제 상신**을 실행하게 된 근거가
"EAP 결재취소로 회수 가능하다"였다(사용자 승인 2026-08-07, CLAUDE.md 안전 경계). 그 회수
경로를 검증한 것이 `e2e/eap_approval_cancel_probe.py` 였고, 이 에이전트는 그 프로브를
프로덕션 그래프로 이식한 것이다 — 즉 **상신의 역방향 짝**이다.

프로브와 다른 점은 대상 지정 방식 하나다. 프로브는 제목 토큰(`E2E_TITLES`)을 환경변수로
받거나 stdin 으로 번호를 물었고, 에이전트는 **HITL(multiselect)로 목록을 띄우고 체크를
받는다**(사용자 요청 2026-08-12).

## 확정된 결정(사용자, 2026-08-12)

- **D1 취소 범위**: ✅ **3단계 전부** — 결재취소 → 상신취소 → 삭제. 문서가 완전히 사라진다.
  (2단계까지만 하면 임시보관문서로 남아 재상신 가능하지만, 사용자는 완전 제거를 택했다.)
- **D2 대상 지정**: ✅ **목록 + 체크**. 제목을 입력받는 프로브 방식 대신, 취소 가능한 문서를
  목록으로 제시하고 체크한 건만 진행한다. 체크 0건이면 아무것도 하지 않는다.
- **D3 노출**: ✅ **hidden(디버그 전용)** — `agent_visibility.HIDDEN_AGENT_IDS`. 목록/상세는
  404 이고, 실행은 관리자 + 프론트 디버그 모드 버튼(회계전표 3종 상세 화면)뿐이다.
- **D4 후보 범위**: 상신문서함(`#UBA1010_UBA`)의 **'진행' 상태 문서**. 종결·반려·회수는
  취소 대상이 아니라 목록에서 빠진다.

## 실측 근거(프로브, 2026-08-07)

Playwright codegen 녹화(`e2e/artifacts/eap_cancel_codegen.py`) + DOM 진단
(`e2e/artifacts/eap_dom_diag.json`)으로 확정한 사실만 코드에 남겼다.

- **EAP 는 dews 그리드가 아니다.** GNB '전자결재' → 같은 탭, iframe `#content_UB` 안의 React
  앱이다. `dewsControl` 계열(`js_lib`)이 전혀 듣지 않아 이 패키지 전용 읽기 JS 두 개를 둔다.
- **행은 `li.listChk`.** 행마다 비어있지 않은 span 은 `기안일: …` 툴팁과 **제목** 2개뿐이고,
  상태는 행 텍스트 끝의 `진행 (결재자)` 패턴이다. 그래서 상태 판정은 **마지막 매치**로 한다
  (제목에 같은 낱말이 섞여도 배지는 항상 끝에 온다).
- **메뉴 셀렉터**: 상신/보관함 그룹 `#UBA_UBA1000` · 상신문서 `#UBA1010_UBA` ·
  임시보관문서 `#UBA1020_UBA` · 미결문서 `#UBA2020_UBA`(그룹 펼침 없이 직접 클릭된다).
- **문서 창은 별도 Page.** 제목 클릭이 `window.open` 을 부른다 — 러너가 `context.on("page")`
  로 자식 스크린캐스트를 자동 부착하므로 라이브 화면에도 그대로 보인다.
- **'확인' 후 창이 스스로 닫히기도 한다.** 3초 관찰 후 안 닫혔으면 직접 닫는다.
- **미결문서 도착이 20s 를 넘긴 사례가 있다.** 결재취소 직후 리스트에 곧바로 안 나타난다.
  → 상한 25s 로 관찰하고, 그래도 없으면 **다른 메뉴로 갔다가 재진입**해 리스트를 강제
  갱신하고 한 번 더 관찰한다(프로브의 회복 경로 그대로).

## 프로브에 없던 가드 — 제목 유일성

문서를 여는 수단이 **제목 부분일치**(`span:has-text(title)`)뿐이라, 목록에 같은 제목이
둘이거나 한 제목이 다른 제목의 부분문자열이면(`출장비` ⊂ `출장비 정산`) 어느 문서가 열릴지
확정할 수 없다. 프로브는 `.first` 로 하나를 골랐지만 — 테스트 문서만 다루니 무해했다 —
실문서에서 그건 **엉뚱한 문서를 지우는 조용한 실패**다.

그래서 브라우저를 건드리기 전에 순수 판정(`nodes.ambiguous_titles`)으로 걸러 낸다: 선택한
제목이 목록에서 정확히 1행에만 나타나지 않으면 **한 건도 진행하지 않고 중단**한다.
(`[행대응]` — FLOW.md 참조.) 취소가 비가역이므로 "모호하면 멈춘다"가 옳은 기본값이다.

## 실패를 다루는 방식

세 단계가 전부 비가역이라 **되감기가 없다**. 한 문서가 중간에서 실패하면:

1. 즉시 중단한다 — 남은 선택 건은 손대지 않는다(부분 상태를 늘리지 않는다).
2. 사유에 그 문서가 **어느 함에 남았는지**를 적는다(상신문서 그대로 / 미결 / 임시보관).
   사람이 이어서 마무리할 수 있어야 하기 때문이다.
3. 앞서 완료된 건 수·제목을 함께 남긴다 — 무엇이 이미 사라졌는지 알 수 있어야 한다.

삭제 후에는 임시보관문서 리스트에서 **부재를 확인**해야 성공으로 친다. 확인이 안 되면
"완료로 보이는데 안 지워진" 상태를 성공으로 단정하지 않고 실패로 끊는다(§10 실패 정책).

## 안전 경계

- **누르는 버튼은 4개뿐이다** — `결재취소`·`상신취소`·`삭제`·`확인`(`steps.ALLOWED_BUTTONS`).
  `click_doc_button` 이 목록 밖 라벨을 클릭 없이 거부한다(상신·보관 오클릭 마지막 방어선).
- **저장(F7)·상신·보관은 어떤 경로로도 클릭하지 않는다.**
- **선택 0건이면 아무것도 하지 않는다.**
- **delay_scale 을 주지 않는다(=1.0).** 프로브가 PASS 한 타이밍이 실시간 그대로였고, 취소는
  비가역이라 검증된 타이밍에서 벗어날 이득이 없다. 관찰 폴은 실시간(`verify.DEFAULT_SLEEP`),
  상한만 `latency.budget_ms` 로 확대한다.

## 알려진 한계

- **첫 페이지만 다룬다.** EAP 리스트는 30행/페이지(실측 2026-08-07)이고 목록은 렌더된 행만
  읽는다. 2페이지 이후 문서는 후보에 오르지 않는다 — 개입 카드 문구에 "첫 페이지"를 명시한다.
- **그래프 라이브 실행 미실시.** 브라우저 조작부는 프로브 이식이지만, 그래프로 묶은 형태의
  라이브 실행은 아직 없다. 첫 실행은 디버그 모드 + 테스트 문서 1건으로 할 것.
