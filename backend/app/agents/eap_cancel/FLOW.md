# 전자결재 상신 취소 — 행위 표기

- 에이전트 `eap-approval-cancel` · 그래프 `build_eap_cancel_graph()`
- 화면 전자결재(EAP, GNB 진입 · iframe `#content_UB`) · 사용자유형 전환 없음
- 표기법 [../ACTIONS.md](../ACTIONS.md) · 근거 [PROCESS.md](PROCESS.md)

상신한 문서를 되돌리는 유일한 에이전트다. 다른 에이전트가 문서를 **만드는** 방향이라면
이쪽은 **지우는** 방향이고, 세 줄이 전부 `확정`(비가역)이다.

`승인필요` 게이트는 **HITL 체크 한 번**이 세 줄 전부를 연다. 문서 한 장의 취소는 세 단계가
한 묶음이고, 중간에서 멈추면 오히려 어중간한 상태로 남기 때문이다.

---

## 다른 계열과 다른 점

**dews 그리드가 아니다.** EAP 는 React 리스트(`li.listChk`)라 `dewsControl` 프리미티브가 전혀
듣지 않는다. 그래서 `js_lib` 대신 이 패키지의 [js.py](js.py) 두 개(읽기 전용)를 쓴다.

**메뉴 딥링크가 없다.** `navigate_schema` 로 갈 수 없어 GNB 를 실클릭해 들어간다.
사용자유형(회계/인사) 전환도 필요 없다 — 전자결재는 유형과 무관하다.

**문서를 제목으로 잡는다.** 리스트에 전표번호 같은 확정 키가 없어 제목 부분일치로 연다.
그래서 `[행대응]` 줄이 선행 조건이다 — 제목이 유일하지 않으면 **한 건도 진행하지 않는다**.

**되감기가 없다.** 세 단계가 전부 비가역이라 실패해도 되돌릴 수 없다. 대신 중단할 때
그 문서가 **어느 함에 남았는지**(상신문서 그대로 / 미결 / 임시보관)를 사유에 적어, 사람이
이어서 마무리할 수 있게 한다. 남은 선택 건은 손대지 않는다.

## 안전 경계

이 에이전트가 누르는 버튼은 `결재취소`·`상신취소`·`삭제`·`확인` 4개가 전부다
(`steps.ALLOWED_BUTTONS`). 상신·저장(F7)·보관은 목록에 없어 브라우저에 닿지 않는다.
hidden 워크플로우라 실행 경로는 관리자 + 프론트 디버그 모드 버튼뿐이다.
