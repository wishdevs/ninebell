# 외상매출금 · 외상매입금 — 행위 표기

- 에이전트 `voucher-trade-receivable`(매출) · `voucher-trade-payable`(매입)
- 그래프 `build_voucher_graph()` — 공유 백본
- 화면 전표조회승인(GLDDOC00700) · 사용자유형 회계
- 표기법 [../ACTIONS.md](../ACTIONS.md) · 근거 [PROCESS.md](PROCESS.md)

미결 전표를 조회해 **결재창을 열어 상신 대기 상태만 확인**한다. 실제 상신은 하지 않는다.

두 에이전트는 **전표유형만 다르고 나머지가 같다.**

| | 외상매출금 | 외상매입금 |
|---|---|---|
| 전표유형 | 국내매출 · 해외매출 | 내수구매 |
| 결재 방식 | 묶음(배치) | 건별 |

---

## 공통 앞단

```
읽기  [읽기]        실행 파라미터: 처리 건수 · 회계일 조회기간(기본 당월)
변경  [로그인]
변경  [유형전환]    회계
변경  [메뉴이동]    전표조회승인 (GLDDOC00700)
변경  [값설정]      작성부서: 전체선택                                     경고
변경  [값설정]      작성자: 지움
변경  [값설정]      회계일: 조회기간                                       중단
변경  [값설정]      전표상태: 미결                                         경고
변경  [값설정]      전자결재상태: 저장                                     경고
변경  [값설정]      전표유형: 매출은 국내매출·해외매출 / 매입은 내수구매    경고
읽기  [조회]        (F2)
읽기  [읽기]        그리드.마스터 — 대상 건수 보고
```

회계일 기간만 `중단` 이다. 기간이 어긋나면 **엉뚱한 달의 전표를 결재창까지 여는** 결과가
되므로 다른 조건과 등급이 다르다.

## 외상매출금 — 묶음 결재

```
읽기  [읽기]        전표별 하위(계정정보) 행수
읽기  [묶음계획]    단독 200건 이상은 단독으로
                    나머지는 합계 200 미만이 되도록 묶음

반복  묶음마다
        변경  [선택해제]  전체
        변경  [행선택]    이 묶음의 전표들
        읽기  [읽기]      체크된 행 집합       확인 계획한 묶음과 일치       중단
        변경  [창열기]    결재창(EAP)          확인 자식창 준비완료          중단
        읽기  [읽기]      자식창의 전표번호들
        분기  계획에 없는 전표번호가 보이면    다른 문서 혼입 — 즉시 중단
              계획한 전표 일부만 보이면        렌더 편차일 수 있어 기록만
        금지  [상신]      미클릭 — '가상 상신' 기록만
        변경  [창닫기]    결재창                확인 부모창 정착
```

## 외상매입금 — 건별 결재

```
반복  전표마다
        읽기  [읽기]      이 행의 전표번호
        변경  [선택해제]  전체
        변경  [행선택]    이 전표
        읽기  [읽기]      체크된 행수          확인 정확히 1개               중단
        변경  [창열기]    결재창(EAP)          확인 자식창 준비완료          중단
        읽기  [읽기]      자식창의 전표번호     확인 대상 행과 일치           중단
        금지  [상신]      미클릭 — '가상 상신' 기록만
        변경  [창닫기]    결재창                확인 부모창 정착
```

## 이 계열의 특징

**확정 등급이 한 줄도 없다.** 아무것도 저장하지 않고 아무것도 상신하지 않는다.
결재창에 하는 일은 렌더 판정을 위한 읽기, 전표번호 읽기, 닫기 셋뿐이다.

**행과 창이 어긋나는 것을 하드 실패로 막는다.** 결재창이 대상 행과 다른 문서를 여는 것이
이 순회의 유일한 위험이라, 열기 직전 체크 상태와 열린 뒤 전표번호를 양쪽에서 대조한다.

**모호한 결과는 중단 근거로 쓰지 않는다.** 전표번호 매치가 0개거나 2개 이상이면
셀렉터 불확실성일 수 있어 기록만 남긴다. **확정적으로 다를 때만** 끊는다.
묶음 결재의 부분 표시도 같은 규율이다 — 계획에 없는 것이 보이면 중단, 계획한 것이
덜 보이면 기록만.

**결재창을 여는 것만으로 흔적이 남는다.** EAP 임시문서가 생길 수 있다. '읽기만 한다'가
곧 '아무 일도 없다'는 뜻은 아니라는 점을 실행 전에 사용자에게 알린다.

## 사용자에게 넘기는 것

실제 상신은 사용자가 전자결재(EAP)에서 직접 일괄 처리한다. 이 에이전트는 대상 전표를
확인해 주는 데까지가 역할이다.
