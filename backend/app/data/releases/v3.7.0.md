### 추가

- **구매발주** — 계획서를 승인하면 에이전트가 ERP 작업을 끝까지 대신합니다: 이동요청 저장 → 발주단위별 구매요청 저장 → 셀프결재 상신 → 구매발주일괄입력에서 거래처 적용·납기·비고 입력 후 발주 저장(발주번호 발급). 되돌릴 수 없는 저장·상신·발주 직전마다 확인 개입이 한 번씩 있어, 화면을 보고 진행 여부를 결정할 수 있습니다. 테스트 프로젝트 3건(ETRI-001~003)에서 구매요청 22건·상신 22건·발주 138건으로 검증했습니다.
- **코드 카탈로그 자동 동기화** — 프로젝트·거래처·예산단위 카탈로그를 브라우저 없이 ERP API 로 매일 자동 갱신합니다(실패 시 기존 브라우저 방식 폴백).

### 개선

- 요청 형식 오류(422)가 났을 때 무엇이 잘못됐는지 응답과 서버 로그에 필드 단위로 표시됩니다.

### 주요 수정

- **구매발주** — 계획서를 제출한 직후 다음 확인 카드가 화면에서 사라져 실행이 멈춘 것처럼 보이던 문제를 고쳤습니다. 제출 응답과 다음 개입 도착이 겹칠 때 새 카드를 지우던 경합이 원인이었습니다.

### 수정

- **법인카드** — 승인번호가 0으로 채워진 내역을 제외하던 규칙을 없앴습니다(거래처가 빈 행만 제외).
- 일부 입력 검증 실패(이메일 형식 등)에서 422 응답 생성 자체가 오류로 터지던 문제를 고쳤습니다.
