# 변경사항(릴리스 노트) 등록 규약

> 대상 독자: 커밋 후 `/changelog` 에 릴리스를 등록하는 사람 또는 Claude Code.
> 화면: `/changelog` (사이드바 Workspace › 변경사항). 소스: `src/app/(app)/changelog`,
> `backend/app/routers/changelog.py`, 모델 `backend/app/models/changelog.py`.

> 릴리스를 **끊는 절차**(버전 결정·파일 커밋·태그)는 `.claude/skills/release/SKILL.md` —
> Claude Code 에게 "릴리스 끊자" 라고 하면 이 문서의 규약대로 작성해 반영한다.

## 원칙

- **한 엔트리 = 한 릴리스**. 개별 커밋 단위가 아니라, 배포/전달 단위로 묶어서 쓴다.
- **릴리스는 리포 파일이 단일 소스** — `backend/app/data/releases/<version>.md`.
  main 푸시 하나가 AWS·온프렘 두 곳에 배포되는데 DB 는 서로 다르다. API 로만 등록하면
  한쪽에만 남으므로, 파일로 두고 스타트업 시드가 없는 버전만 채운다.
- **버전은 semver `vX.Y.Z`** (백필 10건은 날짜식 `2026.07.xx` 로 두고 소급 변경하지 않는다).
- **본문은 마크다운**. 아래 표준 섹션으로 나눈다.
- **읽기는 전 사용자**, 작성·수정·삭제는 관리자(admin+). 백엔드가 최종 강제한다.
- `status='draft'` 는 관리자에게만 보인다. 검토 후 `released` 로 바꿔 공개한다.
- `version` 은 중복 불가 — 중복 등록 시 409.
- 정렬·표기 기준은 `releasedAt` (최신순). 등록 시각(`createdAt`)과 별개로 지정할 수 있다.

## 표준 섹션 6개

커밋 266건을 분류해서 확정한 세트다. 해당 없는 섹션은 그냥 빼면 된다.

| 섹션                | 무엇을 넣나                            | 커밋 타입 대응                |
| ------------------- | -------------------------------------- | ----------------------------- |
| `### 추가`          | 신규 기능·신규 에이전트                | `feat` (순수 신규)            |
| `### 개선`          | 기존 기능 향상 + 속도                  | `perf`, `feat` 중 "개선/전환" |
| `### 주요 수정`     | 잘못 저장·미저장·실행 불가·데이터 훼손 | `fix` 중 결과가 틀렸던 것     |
| `### 수정`          | 표시·조작감 (결과는 정확했음)          | `fix` 중 UI/문구/레이아웃     |
| `### 변경`          | 동작·위치·권한이 달라진 것             | `feat` 중 제거/제약/이동      |
| `### 보안·개인정보` | PII·인증·권한                          | `fix(privacy)`, `feat(auth)`  |

### 주요 수정 vs 수정 — 판정 기준

다음 한 문장으로 결정한다.

> **이 버그 때문에 ERP에 잘못된 데이터가 들어갔거나, 작업이 실패했는가?**

- **예 → `### 주요 수정`** + 엔트리의 `hasMajorFix: true`
  - 예: "저장(F7) 필수값 누락 시 미저장인데 성공으로 오판", "증빙 에디터가 기존 행을 덮어쓰던 사고",
    "세션 쿠키 도메인 문제로 로그인 불가", "카드 적요 PII 노출"
- **아니오 → `### 수정`**
  - 예: "카드 hover 지터", "페이지 이동 시 목록 스크롤 미복귀", "헤더 중복 노출"

`hasMajorFix` 는 본문 파싱 없이 목록 배지·필터를 돌리기 위한 **유일한 구조화 분류 필드**다.
`### 주요 수정` 섹션을 썼으면 반드시 같이 켠다(둘이 어긋나면 배지가 거짓말을 한다).

### 버전 올림 규칙 (semver)

위에서부터 먼저 걸리는 규칙을 적용한다. 판정 근거는 릴리스마다 한 줄로 남긴다.

| 올림           | 조건                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| **메이저** `X` | `### 변경` 섹션이 있음(동작·위치·권한이 바뀜) **또는** 신규 에이전트 추가 |
| **마이너** `Y` | `### 추가` 또는 `### 개선` 이 있음                                        |
| **패치** `Z`   | 수정 계열(`### 수정`·`### 주요 수정`·`### 보안·개인정보`)만 있음          |

### 노트에서 제외할 것

사용자가 체감하지 않는 변경은 넣지 않는다. 실측상 전체 커밋의 약 15%다.

- `ci` · `chore` · `style` · `test` · `docs` · `merge`
- 순수 `refactor` (동작 변화 없음)
- `deploy` 스코프 인프라 작업

배포 담당자에게만 의미 있는 내용이 꼭 필요하면 `status='draft'` 로 남긴다.

### 항목 작성 형식

대상을 **굵은 접두어**로 먼저 밝힌다. 스코프 1위가 `card-collect`(46건)라 "어느 에이전트
얘기인지"가 가장 자주 필요한 정보다.

```markdown
### 주요 수정

- **법인카드** — 필수값이 비어 저장되지 않았는데 성공으로 표시되던 문제 수정
- **외상매출금** — 증빙 2차 적용이 기존 행을 덮어쓰던 문제 수정

### 수정

- **공통** — 목록에서 페이지를 옮길 때 스크롤이 상단으로 돌아오지 않던 문제
```

- 화면·에이전트 이름은 UI 표기 그대로(예: `법인카드`, `외상매출금`).
- 코드 식별자(`BTN_SAVE`, 파일 경로)는 인라인 코드로 감싼다.
- 링크·표는 GFM 그대로 렌더된다(`MarkdownContent` + `remark-gfm`).

## 등록 (관리자 세션 필요)

```http
POST /changelog
Content-Type: application/json

{
  "version": "v1.5.0",
  "title": "변경사항 화면 추가",
  "bodyMd": "### 추가\n- **공통** — 사이드바 **변경사항** 메뉴\n\n### 주요 수정\n- **법인카드** — 팬텀 저장 수정\n",
  "status": "released",
  "hasMajorFix": true,
  "releasedAt": "2026-07-28"
}
```

- `releasedAt` 생략 시 서버 현재시각. 날짜만(`yyyy-mm-dd`) 넘겨도 된다.
- `status` 생략 시 `released`, `hasMajorFix` 생략 시 `false`.
- 응답 201 + 생성된 엔트리(camelCase).

## 나머지 엔드포인트

| 메서드   | 경로                                           | 권한   | 비고                                                        |
| -------- | ---------------------------------------------- | ------ | ----------------------------------------------------------- |
| `GET`    | `/changelog?q&status&hasMajorFix&limit&offset` | 세션   | 일반 사용자는 `released` 만. `status` 는 관리자만 의미 있음 |
| `GET`    | `/changelog/{id}`                              | 세션   | draft 는 관리자 외 404(존재 자체를 숨김)                    |
| `POST`   | `/changelog`                                   | admin+ | 위 참조                                                     |
| `PATCH`  | `/changelog/{id}`                              | admin+ | **전체 교체** — 모든 필드를 다시 보낸다                     |
| `DELETE` | `/changelog/{id}`                              | admin+ | 204                                                         |

`hasMajorFix` 는 생략하면 필터 없음, `true`/`false` 를 주면 해당 릴리스만 반환한다.
`PATCH` 는 전체 교체라 `hasMajorFix` 를 빼면 `false` 로 돌아간다.
